# Roadmap tecnológico 2026–2029

## Estado

Hipótesis inicial de trabajo. Los horizontes y fechas deberán ajustarse después de validar el AS-IS, medir la línea base y ejecutar las PoC. El roadmap no representa un compromiso de implementación inmediata.

## Objetivo

Ordenar iniciativas y dependencias para evolucionar el ERP hacia un ecosistema que reutilice datos históricos confiables en planificación, presupuestación y control económico.

## Secuencia preliminar

| Horizonte | Propósito | Iniciativas candidatas | Condición de avance |
|---|---|---|---|
| 2026 — Validar y medir | Comprender el estado actual | AS-IS, inventario de datos, línea base, reglas de calidad, métricas de rendimiento | Datos y brecha validados |
| 2027 — Integrar y visualizar | Crear capacidades base | APIs, gobierno de datos, modelo analítico proporcional, BI y observabilidad | Indicadores confiables y uso comprobado |
| 2028 — Experimentar | Evaluar capacidades de mayor incertidumbre | PoC de arquitectura analítica, IA generativa supervisada y posible RAG | Resultados medibles, riesgos controlados y costo aceptable |
| 2029 — Consolidar y escalar | Operar solo lo que demostró valor | Automatización controlada, optimización, FinOps y actualización arquitectónica | Beneficio sostenido y capacidad operativa |

## Dependencias principales

```text
AS-IS validado
  → Línea base y calidad de datos
    → Integración y gobierno
      → BI y comparación previsto-real
        → PoC de arquitectura e IA
          → Evaluación económica, seguridad y escalamiento
```

## Iniciativas que no deben adelantarse

- Agentes con capacidad de modificar presupuestos o ejecutar acciones en el ERP.
- Platform Engineering sin evidencia de fricción y escala suficientes.
- Arquitectura orientada a eventos sin necesidad verificable de baja latencia.
- FinOps avanzado sin consumo cloud o de IA material.
- IA generativa sobre información no validada.

## Campos por iniciativa

| Campo | Descripción |
|---|---|
| Iniciativa | Capacidad o resultado esperado |
| Responsable | Rol o integrante responsable |
| Prerrequisitos | Datos, decisiones o capacidades necesarias |
| Evidencia | Fuente, medición o PoC que la justifica |
| Criterio de entrada | Condición para iniciarla |
| Criterio de salida | Resultado verificable |
| Riesgos | Identificadores de la matriz de riesgos |
| Estado | Propuesta, aprobada, en curso, validada o descartada |
